# 🏗 Архитектура проекта ClothingStore (CatVTON Shop)

## 📋 Краткое описание
Fullstack-приложение интернет-магазина одежды с интеграцией нейросетевой модели CatVTON для виртуальной примерки.

## 🛠 Технологический стек

### Backend
- **Python 3.12** + **FastAPI** (асинхронный веб-фреймворк)
- **SQLAlchemy 2.0** (async) + **Alembic** (миграции)
- **PostgreSQL 16** + **Redis 7**
- **Celery** + **Celery Beat** (фоновые задачи)
- **Pydantic v2** (валидация данных)
- **Poetry** (управление зависимостями)

### Frontend
- **React 18** + **Vite 5**
- **Ant Design 5** (UI-компоненты)
- **React Router v6** (маршрутизация)
- **Axios** (HTTP-клиент с interceptors)
- **React Context** (управление состоянием — НЕ Zustand!)

### Инфраструктура
- **Docker Compose** (6 контейнеров)
- **Nginx** (reverse proxy + раздача статики)
- **Makefile** (автоматизация)

### ML
- **CatVTON** — диффузионная модель виртуальной примерки
- Fallback-механизм при недоступности GPU

## 🏛 Архитектурные решения

## 📝 Шаблоны описаний для рисунков

### Перед каждым рисунком нужно:
1. Описать **требования** к разработке/проектированию
2. Использовать слова **«разработано»** или **«спроектировано»**
3. Сначала что-то написать про рисунок и только затем сделать ссылку **«на рисунке N представлено...»**. потом можно продолжить текст
4. Стиль: академический, научный, объективный. Избегай разговорных выражений, местоимений «я» или «мы» (используй безличные конструкции: «было разработано/спроектировано», «проведен анализ»).

### Примеры:

**Перед рисунком схемы БД:**
> «Для хранения информации о пользователях, товарах, заказах и сессиях примерки требовалось спроектировать реляционную базу данных, удовлетворяющую правилам третьей нормальной формы. В соответствии с этими требованиями **спроектирована** схема базы данных веб-приложения, представленная на рисунке 3.»

**Перед рисунком листинга кода:**
> «Для абстрагирования логики получения товаров с учётом фильтров, пагинации и жадной загрузки связей требовалось разработать метод репозитория. **Разработан** метод `read_all_with_relations`, реализация которого представлена на рисунке 10.»

**Перед скриншотом страницы:**
> «Для предоставления пользователю возможности управления отложенными покупками требовалось спроектировать интерфейс страницы избранного. **Спроектирована** страница с табличным представлением товаров, которая показана на рисунке 18.»
